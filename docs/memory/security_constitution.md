# Security Constitution — Dawa24 Store

**Status**: RATIFIED  
**Ratification Date**: 2026-09-16  
**Scope**: Full Dawa24 Store Codebase (Go Modular Monolith, PostgreSQL, Redis, MinIO/S3, MuhiyaLLM Gateway)  
**Applicable Standards**: OWASP Top 10 (2021/2025), OWASP ASVS Level 2, Egyptian Data Protection Law No. 151/2020  

---

## 1. Trust Boundaries & Attack Surface

### 1.1 Untrusted Zones (External / Hostile)
- **Public Internet Clients**: Any HTTP client contacting public endpoints (`/auth/*`, `/catalog`, `/suppliers`, `/static/*`, `/health`). All incoming headers (`X-Forwarded-For`, `User-Agent`, `Referer`, `Host`) and request payloads (JSON, form body, query params, uploaded files) are untrusted.
- **Client Browsers**: Browser DOM context and client-side JavaScript execution. Client cookies and form submissions must be validated via double-submit CSRF and strict origin/referrer checks.
- **AI Gateway Responses**: Content generated by upstream AI models via MuhiyaLLM Gateway (`product.match`, `assistant`, `chat`) is untrusted text and must be sanitized before rendering into HTML.

### 1.2 Semi-Trusted Zones (Authenticated Tenancy & M2M Bridges)
- **Authenticated Tenancy**: Customers (Pharmacies) and Vendors (Suppliers). Authenticated identity is trusted only up to the verified session actor (`authctx.Actor`). A tenant must NEVER be trusted to access or mutate another tenant's data. Cross-tenant boundaries are strictly enforced.
- **M2M Integration Bridges**: Webhook and messaging endpoints (`/telegram/*`, `/whatsapp/*`, `/marketing/*`). Authenticated strictly via pre-shared Bearer tokens (`TELEGRAM_BRIDGE_TOKEN`, `WHATSAPP_BRIDGE_TOKEN`, `MARKETING_BRIDGE_TOKEN`). Must run under rate limits and input sanitization without inheriting ambient user session authority.

### 1.3 Trusted Zones (Internal Core)
- **Application Core**: In-memory domain services (`internal/modules/*`, `internal/platform/*`).
- **Database Network Boundary**: PostgreSQL (port 5432) and Redis (port 6379) MUST run on isolated private container/host networks, bound strictly to internal interfaces (`127.0.0.1` or docker bridge). Never expose directly to the public web.
- **System Actor (`database.AsSystem`)**: Privileged internal operations (platform migrations, cross-tenant background worker jobs, admin reporting). Every invocation is a deliberate isolation bypass and must be logged and greppable.

## 2. Authentication & Authorization Standards

### 2.1 Identity & Session Management
- **Session Tokens**: Cryptographically random session identifiers (HMAC-signed, $\ge 32$-byte `SESSION_SECRET`), stored in Redis (`dawa24:session:*`).
- **Session Lifecycle**: 
  - Absolute TTL: 720 hours (30 days).
  - Idle Timeout: Strict 30 minutes of inactivity; automated background poll requests must NOT refresh idle timers.
  - Concurrency & Eviction: Duplicate logins must invalidate or evict previous sessions per security policy.
- **Cookies**: Session cookies (`dawa24_session`) MUST have flags: `HttpOnly = true`, `SameSite = Lax` (or `Strict`), and `Secure = true` in staging and production (`SESSION_SECURE=true`).
- **Password Hashing**: `golang.org/x/crypto/bcrypt` with minimum cost parameter of 12. Plaintext passwords must never appear in logs or error traces.
- **Account Lockout**: After 5 consecutive failed login attempts (`MaxFailedLoginsBeforeLockout`), the account is locked for at least 15 minutes (`DefaultLockoutDuration`).
- **MFA / Step-up**: TOTP secrets must be encrypted at rest in PostgreSQL via `pgcrypto`.

### 2.2 Access Control & RBAC
- **Actor Resolution**: All authenticated handlers must extract the caller exclusively from `authctx.From(ctx)`. Handlers must never trust client-supplied user IDs, org IDs, or roles from query params or form bodies.
- **Role Verification**: Route groups must apply explicit RBAC middleware:
  - `authctx.RequireCustomer` for pharmacy operations.
  - `authctx.RequireVendor` for supplier operations.
  - `authctx.RequireStaff` for backoffice admin.
  - `authctx.RequireApproved` for trading operations (orders, quotes, cart checkout, offer publishing).
- **KYC Document Gate**: Organizations with unapproved status or missing mandatory regulatory documents (`attachSvc.MissingRequiredDocuments`) must be blocked from financial transactions and trading.
- **Permission Cache Invalidation**: Dynamic permissions are validated against `identity.rbac_version`. Role or permission changes must increment this version or flush Redis cache to ensure instantaneous propagation.

## 3. Data Isolation & Privacy Rules

### 3.1 Multi-Tenant Database Isolation
- **Tenant Context in DB Transactions**: All tenant-scoped operations must execute inside `database.DB.InTx` or `database.DB.InReadTx`. These execute `SET LOCAL app.current_org_id = <org_id>`.
- **Engine-Level Row-Level Security (RLS)**: Every tenant-owned table must have `ENABLE ROW LEVEL SECURITY`, `FORCE ROW LEVEL SECURITY`, and a policy calling `platform.tenant_visible(organization_id)`.
- **Defense-in-Depth Query Scoping**: Repository SQL queries must explicitly include `WHERE organization_id = $X` even when RLS is active.
- **App DB Role Constraint (High Priority)**: The production application MUST NOT connect as PostgreSQL superuser (`postgres`). Superusers bypass RLS by design in PostgreSQL (`rlsBypassed=true`). A dedicated restricted application role (e.g. `dawa24_app`) must own and execute runtime queries.
- **Cross-Tenant Guardrail**: Every tenant-owned entity repository MUST have automated tests asserting that an organization cannot read, update, or delete rows belonging to another organization.

### 3.2 Financial Precision & Invariants
- **Zero Float Rule (Non-negotiable)**: Floating-point types (`float32`, `float64`) are strictly forbidden for currency, prices, discounts, wallet balances, or fee calculations.
- **Money Representation**: All currency values must use `internal/shared/money.Amount` representing minor units (cents/piastres) as integers. Stored in PostgreSQL as `NUMERIC(p, 2)`.

### 3.3 Data Privacy & PII / PHI Protection
- **Medical & Syndicate Credentials**: Pharmacist national IDs, syndicate registration numbers, and commercial licenses must be accessible only to the owning user and authorized platform compliance reviewers.
- **Audit Logs**: Logs must scrub PII, passwords, session tokens, TOTP secrets, and credit/wallet credentials before writing.

## 4. Secrets Management Policy

### 4.1 Secret Sourcing & Validation
- **Configuration Loading**: All secrets must be loaded via environment variables at application startup in `internal/platform/config`.
- **Fail-Fast Startup**: The process must immediately panic / refuse to start if mandatory secrets (`DATABASE_URL`, `REDIS_URL`, `SESSION_SECRET`, `GATEWAY_VIRTUAL_KEY` when AI enabled) are missing or fail length/entropy checks.
- **Zero Hardcoded Secrets**: No credentials, private keys, API secrets, or passwords may be committed to version control.

### 4.2 AI Gateway Secret Decoupling
- **Zero Upstream Provider Secrets**: The Store repository must NEVER contain OpenAI, Anthropic, Google, or other model provider keys.
- **Capability-Based Virtual Keys**: The Store only holds a single `GATEWAY_VIRTUAL_KEY` granting access to MuhiyaLLM Gateway capability aliases.

## 5. Secure-by-Design Patterns

### 5.1 Injection Prevention
- **SQL Injection**: Dynamic string concatenation into SQL queries is strictly prohibited. All SQL queries must use parameterized placeholders (`$1, $2, ...`) via `pgx/v5`.
- **Admin SQL Console**: Any admin dataset exploration console (e.g. `dawa24_sql_console`) must run under an unprivileged `SELECT`-only database role with credentials and secret columns explicitly excluded.
- **XSS & Template Escaping**: All dynamic data in templates must be escaped. Templ components provide default contextual escaping. Raw HTML injection (`templ.Raw`) is forbidden unless sanitizing trusted markdown.
- **CSP Nonce Enforcement**: Inline `<script>` tags must strictly carry a per-request cryptographic nonce generated by `httpx.SecurityHeaders` and accessed via `layouts.Nonce(ctx)`.
- **Technical Debt Remediation**:
  - Migrate away from Alpine.js `unsafe-eval` by adopting `@alpinejs/csp`.
  - Convert remaining inline `on*=` event handlers to `addEventListener` or Alpine directives to eliminate `script-src-attr 'unsafe-inline'`.

### 5.2 Request Forgery & Open Redirects
- **Double-Submit CSRF**: State-mutating requests (`POST`, `PUT`, `PATCH`, `DELETE`) must carry a valid `X-CSRF-Token` header or `_csrf` form parameter matching the `dawa_csrf` cookie.
- **Constant-Time Comparison**: CSRF verification must use `crypto/subtle.ConstantTimeCompare`.
- **Local Redirect Enforcement**: Any handler issuing an HTTP redirect based on user input or `Referer` (e.g., login return paths) must sanitize the destination using `internal/ui/safeLocalRedirect`. Unvalidated external redirects are strictly prohibited.

### 5.3 Anti-Scraping & Resource Exhaustion
- **Anti-Scraping Guards**: Public listing endpoints (`/catalog`, `/suppliers`) are protected by `antiscrape` middleware:
  - Anonymous pagination capped at `GuestMaxPage` (25) and `GuestMaxPageSize` (48).
  - Honeypot form trips incur an automatic 1-hour refusal penalty (`PenaltyTTL`).
  - Response header `Content-Signal: ai-train=no, ai-input=no` set on all public HTML responses.
- **Rate Limiting**: Multi-tiered Redis rate limiters (`httpx.Limiter`):
  - IP-based limits for unauthenticated endpoints (60 req/min).
  - User/Org-based limits for authenticated APIs (240 req/min).
  - Fails open on Redis errors to prevent operational denial of service.
- **Statement & Request Timeouts**:
  - HTTP request context timeout: 25 seconds.
  - PostgreSQL statement timeout: 30 seconds for web queries, 10 minutes for worker bulk imports.

### 5.4 File Upload Security
- **Strict File Type Whitelist**: Uploads permitted only for strictly whitelisted MIME types and extensions: PDF (`application/pdf`), PNG (`image/png`), JPEG (`image/jpeg`), and WEBP (`image/webp`).
- **Storage Isolation**: Sensitive verification/KYC documents must be segregated from public asset storage. Verification documents must never be served with permanent public read access; they must require authenticated presigned URLs or application-gated streaming.
- **Path Traversal**: Filenames must be generated as UUIDs or unguessable hashes. Original client filenames must never be used directly on the filesystem.

## 6. API & Integration Security

### 6.1 Machine-to-Machine (M2M) Integrations
- Static Bearer tokens for external services (Telegram webhook, WhatsApp bridge, Marketing digest) must be cryptographically high entropy ($\ge 32$ bytes).
- M2M endpoints must be mounted on dedicated routes and must validate tokens in constant time.
- Recommended hardening: In production, enforce reverse proxy IP allowlisting (n8n host only) or HMAC webhook signature verification.

### 6.2 AI Capabilities & Offline Determinism
- **Fallback Rule**: Every AI capability call (`ai.Client`) must catch errors, timeouts, or disabled states (`GATEWAY_ENABLED=false`) and execute a deterministic algorithmic fallback. A pharmacy must always be able to complete an order, and a supplier must always be able to import inventory when the AI Gateway is unreachable.
- **SSRF Protection**: Outbound HTTP requests to user-supplied URLs are prohibited. Any administrative endpoint testing external connections (`FetchGatewayModels`) must be restricted strictly to Platform Super Admins.

---

## 7. Audit, Logging & Monitoring

- **Structured Logging**: All logs emitted as structured JSON (`log/slog`) with correlated `X-Request-ID`.
- **Sensitive Data Masking**: Request bodies containing passwords, credit card numbers, or session secrets must never be logged.
- **Security Alerting**: Critical events (recovered panics, multiple failed login bursts, CSRF failures, rate limit exhaustion, unauthorized cross-tenant query attempts) must be reported to error tracking (`errtrack`).

## 8. Compliance & Standards Mapping

- **OWASP Top 10 (2021/2025)**:
  - *A01 Broken Access Control*: Mitigated by strict DB RLS (`platform.tenant_visible`), `authctx` actor resolution, and repository query scoping.
  - *A02 Cryptographic Failures*: Enforced HSTS (1 year), TLS 1.2/1.3, bcrypt (cost 12), pgcrypto for TOTP secrets, high-entropy tokens.
  - *A03 Injection*: Strict parameterized queries via `pgx`, templ contextual HTML escaping, absence of raw shell execs.
  - *A04 Insecure Design*: Non-negotiable `money.Amount` integer arithmetic, deterministic AI fallbacks, KYC trade gates.
  - *A05 Security Misconfiguration*: Fail-fast startup configuration checks, production HTTPS enforcement, security headers (nosniff, SAMEORIGIN).
  - *A07 Identification & Authentication Failures*: Redis-backed sessions, 30m idle timeouts, lockout after 5 failed attempts, TOTP MFA.
  - *A08 Software & Data Integrity Failures*: Dependency pinning via `go.sum`, CSRF double-submit validation, strict MIME verification.
- **OWASP ASVS Level 2**: Standards for multi-tenant SaaS and healthcare/B2B commerce architectures.
- **Egyptian Data Protection Law (No. 151/2020)**: Confidentiality of commercial transactions, pharmacy licenses, and personal syndicate data.

## 9. Evidence, Assumptions & Technical Debt

### 9.1 Confirmed Repository Evidence Paths
- `AGENTS.md`: Non-negotiable money rules, AI isolation, RLS rules, and file size ceilings.
- `docs/SECURITY_HARDENING.md`: Deploy actions, CSP state, and operator security checklist.
- `internal/platform/httpx/middleware.go`: Security headers, per-request CSP nonce, trusted hop client IP resolution.
- `internal/platform/httpx/csrf.go`: Double-submit cookie verification.
- `internal/platform/database/query_helpers.go`: Tenant scoping (`applyTenant`), `AsSystem`, and `UnscopedTables`.
- `internal/platform/config/config.go`: Startup secret checks and production validations.
- `internal/modules/identity/domain.go`: Password hashing, lockout constants, session domain types.

### 9.2 Active Technical Debt & Accepted Risks
- **Postgres Superuser Connection (High)**: While developing or running as superuser `postgres`, database-level RLS is bypassed. Mitigated in code by `WHERE organization_id = $X` in repositories, but requires deploying a non-superuser DB role for strict DB-level defense.
- **CSP Transitional Allowances (Medium)**: Alpine.js uses `'unsafe-eval'`, and legacy template attributes use `script-src-attr 'unsafe-inline'`. Nonces protect `<script>` tags, but full CSP hardening requires migrating to `@alpinejs/csp` and removing inline `on*=` handlers.

## 10. Governance & Exception Process

- **Ownership**: The Dawa24 Security & Platform Core Engineering Team.
- **Enforcement**: Automated CI lint gates (`make check`), automated unit and integration tests, and periodic `/speckit-security-review-audit` runs.
- **Exceptions**: Any intentional bypass of tenant isolation must use `database.AsSystem(ctx)` with an accompanying inline code comment documenting the business justification and security rationale.
- **Review Cadence**: Reviewed and re-verified at every major milestone release, or upon introducing any new external network boundary.
