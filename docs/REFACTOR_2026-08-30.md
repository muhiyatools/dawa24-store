## Security

### The Gateway administrator credential

`platform_admin.system_settings['gateway_configuration'].api_key` held
`postgres:<password>` — the production PostgreSQL superuser credential.
`gateway.NewAdminClient` splits that on the colon and sends it as HTTP Basic
auth to `api.muhiya.com` on every provisioning, plan-listing, usage and log
call. It had been doing so since the field was filled in.

`ValidateAdminCredential` already existed and already rejected this shape, but
it only ran on save, which protects nothing already stored.

- `GatewaySettings.AdminCredentials` now returns empty for a value that fails
  validation, so a bad credential cannot leave the process through any caller,
  and `CanProvision` reports false so callers degrade to their fallback.
- The connection-test endpoint validates the credential typed into it, on the
  same terms, before opening a client.
- The stored value was cleared in the live database. The organization's virtual
  key (`sk-virt-…`) was left intact, so AI completions still work; only Gateway
  *management* calls are disabled until a real administrator credential is
  entered.

**Still required, and only you can do it:** rotate the PostgreSQL password and
the Gateway administrator credential. The old password was transmitted to a
third-party host repeatedly and was pasted into an AI session. Clearing the
field does not un-send it.

### Content-Security-Policy

`script-src` no longer names `unpkg.com`, `cdnjs.cloudflare.com` or
`cdn.jsdelivr.net`, because nothing is loaded from them any more. `default-src`
dropped its blanket `https: data: blob:`, `connect-src` dropped `http:` and the
websocket schemes, and `object-src 'none'` and `frame-ancestors 'self'` were
added.

`'unsafe-inline'` and `'unsafe-eval'` remain and are load-bearing: 56 inline
`<script>` blocks live in the templates, and Alpine 3 compiles expressions with
`new Function`. Removing them means moving those blocks into `app.js` and
switching to Alpine's CSP build. That is written down in the middleware rather
than implied away.

## Database

Four migrations, all applied to the live database.

**`149_rls_gap_closure`** — nine tables carrying `organization_id` had no
row-level security at all, four of them holding money or identity records.
They now have `ENABLE` + `FORCE` and a `tenant_isolation` policy, following the
existing convention that a NULL organization means a platform-owned row.
Separately, 76 tables had RLS enabled but not forced; every table in this
database is owned by `postgres`, so without `FORCE` any connection as the owner
read across tenants silently.

Verified after the fact by connecting as `dawa24_app` and counting: with no
tenant context it sees 26 of 32 audit rows, 0 of 36 documents and 8,284 of
10,026 match decisions; with `app.is_system` set it sees all of them. That is
the intended behaviour, and it confirms the policies actually bind. The only
code that reaches `db.Pool()` directly is River's queue driver, which operates
on unprotected `public.river_*` tables.

**`150_foreign_key_indexes`** — Postgres creates no index for a foreign key, so
each of the 35 unindexed ones meant a sequential scan on every join through it
and on every delete of a referenced row. Twenty-two of the thirty-five were in
`promo` and `smartorder`. `ingest.catalog_import_rows` has 77,054 rows and had
three of them.

**`151_duplicate_index_cleanup`** — nine indexes duplicating another on the same
table, columns and predicate. In each case the survivor is the one that also
enforces a constraint, or the one whose name says what it is for.

Indexes that are merely *unused* were left alone. Thirty have never been
scanned, which is suggestive but not conclusive — a feature nobody has exercised
cannot have used its index — and `pg_stat_statements` cannot be installed on
this instance because `shared_preload_libraries` is empty and only a server
restart can change that. **Ask Elestio to add it.** Query optimisation without
it is guesswork.

**`152_retire_dead_tables`** — twenty tables that were empty in production *and*
referenced nowhere in Go or templ. Both conditions had to hold; 47 tables that
are empty but still referenced were left in place. Three that met both
conditions were also kept because a live table still points at them by foreign
key (`billing.payment_integrations`, `inventory.father_user_temparte_warehouses`
and, transitively, the table it anchors). The down migration recreates all
twenty with columns, types, defaults and primary keys, generated from the live
schema before the drop; it does not restore their foreign keys or secondary
indexes, and says so.

### Migration drift

`schema_migrations` records version 48, `seed_realistic_data`, applied on
17 August. Its file no longer exists. The runner checksums applied migrations
but iterates over *files*, so a migration present only in the ledger was
invisible to it: this database could not be rebuilt from the repository and
nothing said so.

`(*DB).Orphans` reports the condition, `migrate` logs it at start-up, and
`cli migrate-status` prints it and exits 3. It reports rather than refuses,
because refusing to boot would strand a running deployment over a file that is
already gone.

**Still open:** either reconstruct migration 48 or write it off in `docs/adr/`.

## Backend

- **Two `go vet` findings fixed.** `session.UpdatedAt = session.UpdatedAt` in
  the customer and vendor team-import handlers was meant to touch the
  timestamp; it now does.
- **Three of five confirmed N+1 sites batched.** The public jobs list and the
  admin jobs list each called `GetOrganization` once per vacancy; the favourites
  page called `GetProduct` once per favourite, against a 50,220-row table. The
  batch helpers (`org.Service.GetOrganizations`, `catalog.Service.ProductsByIDs`)
  already existed — the loops simply did not use them.
- **The test suite no longer destroys tracked files.** `saveUploadedFile` and
  `saveUploadedBytes` mirrored every write into the relative `data/uploads`
  directory even when `UPLOAD_DIR` was configured, so configuration could
  redirect reads but never writes. A test also called
  `os.RemoveAll(UploadBaseDir)` on the *default* directory. Between them, a
  plain `go test ./...` deleted 166 committed files and wrote 166 replacements.
  The dual-write is gone, `TestMain` points uploads at a temporary directory,
  and `.gitignore` covers the whole uploads tree.
- **22 pre-existing unformatted files** were formatted. `make check`'s
  `fmt-check` gate had been failing before this session.

## Frontend

- **Vendor assets are served from this application.** htmx 1.9.10, Alpine 3.13.5
  and Leaflet 1.9.4 were loaded from unpkg and cdnjs on every request; Alpine and
  Leaflet carried no integrity attribute. All four downloads were verified
  against the SRI hashes that were pinned in the templates before being moved
  (htmx sha384, Leaflet CSS and JS sha256 — all matched).
- **Leaflet is no longer on the critical path.** It was requested by every page
  in the platform and is used by two. `app.js` gained `ensureLeaflet`, which
  injects it when a map element is present and reports a failure on the element
  instead of leaving an empty box. The suppliers page was loading it a second
  time from unpkg and now shares the same loader.
- **Asset URLs carry a content hash.** `ui.AssetURL` computes it from the
  embedded file and `layouts.Asset` is installed with it at start-up. The
  hand-typed version strings had already drifted — stylesheets said
  `?v=2026082903` while `app.js` said `?v=2026082901`, so a CSS change could
  ship without the JavaScript that belonged with it.
- **Twenty tables were rendering unstyled.** Fourteen carried `class="table"`
  and six `class="b2b-table"`; neither class is defined in any stylesheet, so
  those tables fell back to browser defaults — no header treatment, no row
  borders, no hover, no dark-theme colours. They now use `.data-table`, and the
  inline declarations that restated what `.data-table` already provides were
  removed with them. Every table in the platform now uses one contract, except
  four with their own defined styles (invoice print, savings, preview).
- **311 inline style attributes removed** by mapping exact repeated values onto
  utility classes (five more went with the table fix above, 316 in total). Thirteen existing utilities covered most of it; seven new
  ones were added for patterns that appeared ten or more times, each documented
  with the count it replaced. Only exact whole-attribute matches were rewritten,
  so nothing changed visually.
- **Four tests now guard the layout**: no CDN hosts, no Leaflet in the head,
  every local asset URL carrying its file's hash, and the shell always
  rendering. `internal/ui/layouts` previously had no tests at all.

The `Base` template used to wrap its entire body in `if site != nil`.
`GetSiteSettings` never returns nil — it falls back to a complete default — so
that branch could not fire. It was removed rather than left implying a failure
mode that does not exist.

## What was not done

Honest list. None of this is blocked; there was simply not time.

- **101 Go files still exceed the 400-line limit**, including
  `admin_handlers.go` at 3,149 lines. `internal/ui` is still 148 files in one
  flat package behind a single 25-dependency struct, serving admin, vendor and
  customer alike. Splitting it by audience is the largest remaining backend job
  and everything else in the handler layer gets easier after it.
- **2,507 Arabic string literals remain in Go.** An English-language user is
  still served Arabic from the backend. One was moved as a worked example
  (`admin.jobs_unknown_company`); the pattern is `i18n.T(lang, key)` plus a
  `addKey` line in `internal/shared/i18n/catalog_*.go`.
- **4,042 inline styles remain.** The long tail needs page-by-page work, not
  another sweep — the repeated patterns are gone.
- **672 emoji and 100 inline `<svg>` blocks remain in templates**, and 56
  components are still unused, including every button, form field, tab, toast,
  skeleton and the `DataTable`. Pages hand-roll all of it.
- **Two N+1 sites remain**: `coverage_handlers.go:210` (`GetCity` per selected
  city — bounded by form input against a 351-row table, so low priority, and it
  needs a new batch repository method) and `compare_results_handlers.go:49`
  (`GetFile` per id).
- **Seventeen handlers still fetch with a hardcoded limit and no pagination**,
  including three 500-row fetches.
- **Twelve ad-hoc breakpoints** and no breakpoint scale.
- **`pg_stat_statements` is not installed**, so there is still no query-level
  evidence for what is actually slow.
- **No repository-layer tests.** Every `postgres/` package, plus
  `platform/config`, `cache`, `features` and `observability`, still has none —
  which is the safety net the remaining structural work needs most.
- **The application was never booted end to end** during this session: there is
  no Redis or Docker on the machine it ran on, and the server requires both.
  Everything above is verified by compilation, tests, template rendering and
  direct database queries — not by clicking through the running product.

## One render path instead of two hundred

`UIHandler.renderPage` replaces 201 copies of the same three lines — set the
content type, render, log the error. Copies are how a response path drifts: a
handler that forgets the content type serves HTML as `text/plain`, and one that
drops the error check loses the only signal a page failed halfway through. The
19 that remain are genuinely different — an explicit status code, extra log
fields, a fallback to `renderError` — and were left rather than forced into a
shape that does not fit.

The helper documents why a render error is logged and not surfaced: by the time
templ fails, bytes are usually already on the wire, so the response cannot
become a 500. Handlers that need to fail *before* rendering still call
`renderError`.

## The three god files are gone

`admin_handlers.go` was 3,149 lines, `customer_handlers.go` 2,223,
`vendor_handlers.go` 1,997. They are now 121, 434 and 142, with their contents
moved into 30 files named for what they do — settings, approvals, products,
billing, geography, developers, audit, institutional, documents, users,
commerce; cart, checkout, orders, branches, employees, notifications; variants,
team, inventory, offers, ingest samples.

Nothing was edited in the move. Declarations were relocated verbatim inside the
same package, so no call site, signature or visibility changed; `goimports`
pruned each new file's imports. Twelve more files were split the same way,
including `handlers.go` (routes now separate from the request helpers and the
constructor) and `public_handlers.go` (authentication separated from the public
pages).

The largest file in `internal/ui` is now 543 lines. The oversized *count* only
moved from 101 to 93 because several of the new files are still in the 400–550
band — but no file in the web layer is now beyond one sitting's reading.

## Emoji, and why a blanket delete was the wrong tool

The first attempt deleted every decorative emoji. It broke the build, and the
way it broke was the useful part: an `if` branch whose only content was a lock
emoji became an empty branch, which templ rejects outright, and a delete button
whose only content was a wastebasket became an invisible control. Deleting
decoration is safe; deleting the *only* content of an element is not.

The second attempt separates three cases:

- **Sole content of an element or branch** → replaced with the matching icon
  from `internal/ui/components/icons.templ`. 398 of these.
- **Inline beside text** ("📦 Orders") → deleted, taking at most one following
  space so the surrounding words keep their spacing. 600 of these.
- **No icon means the same thing** → left alone. 46 remain, mostly status dots
  (🟢 🔴) and one-off glyphs that want a design decision rather than a sweep.

Decoration was also removed from four i18n catalogue files. A translated string
should not carry an emoji: it is not translatable, it is not part of the
meaning, and it appears in every language.

**Deliberately not touched:** `internal/ui/visitor.go` stores country names with
flag emoji (`"مصر 🇪🇬"`), and `platform_admin/postgres/visitors.go` has SQL that
compares against those exact strings. Stripping one without the other would
silently stop matching rows that are already in the database. Structs with an
`Icon string` field holding an emoji (`pages/wizard.go`,
`admin_import_wizard.go`, `ingest/catalog_import.go`, `identity/domain.go`) were
also left: converting them means changing every render site, which is a change
per site rather than a sweep.

## N+1 queries: none left, and two of the five were misjudged

The favourites page, the public jobs list and the admin jobs list were genuinely
unbounded — one query per row of whatever the page displayed — and are batched.

The vendor coverage form called `GetCity` once per selected city; a vendor
covering a governorate submits dozens at a time. It now reads the 351-row city
table once and indexes it.

The fifth, in `compare_results_handlers.go`, turned out not to be an N+1 at all:
an explicit guard three lines above caps the loop at ten files. Recorded here
rather than quietly dropped from the count.

## Arabic literals moved onto the i18n engine — 231 converted

The engine existed and worked: `i18n.T(lang, "key")`, with keys declared by
`addKey(e, key, namespace, textAR, textEN, description)` in
`internal/shared/i18n/catalog_*.go`. Only one key had been used as a worked
example before this pass.

**Customer surface — strict, complete.** Every Arabic string literal in every
`customer_*.go` handler file was moved to an i18n key:

- `customer_saving_handlers.go` — 24 literals (form validation, CRUD notices,
  Excel export headers, the `"غير مرتبط"` cell value).
- `customer_order_handlers.go` — 16 literals (order edit errors, review
  success, negotiation flow, notification dispatch). The notification goroutine
  captures `lang` before launching so the message reaches the supplier in the
  pharmacy's chosen language.
- `customer_saving_import_json.go` — 25 literals (file upload errors, preview
  JSON errors, progress messages in the background goroutine, commit/cancel
  responses). The goroutine gained a `lang string` parameter for progress text.
- `customer_saving_import_handlers.go` — 16 literals (upload errors, session
  not found, Excel/CSV sample template headers).
- `customer_cart_handlers.go` — 9 literals (cart access denial, coverage
  reasons, add-to-cart success toast). HX-Trigger toast messages were
  converted from raw JSON strings to `fmt.Sprintf` with `i18n.T`.
- `customer_cart_offer_handlers.go` — 12 literals (offer purchase denial,
  invalid offer, add-to-cart success/failure, availability check failure).
- `customer_branch_handlers.go` — 10 literals (branch CRUD, cannot-delete-main,
  invalid ID).
- `customer_team_handlers.go` — 13 literals (team import flow, session
  validation, column mapping errors).
- `customer_employee_handlers.go` — 10 literals (employee CRUD, cannot-remove-
  self, status toggle).
- `customer_user_org_handlers.go` — 8 literals (vendor link create/update/
  delete, validation, default vendor name fallback).

**Vendor surface — strict, partial.** The saving, warehouse, team, branch and
ingest AI-state handlers were converted (85 literals). The ingest sample,
catalog, order, sponsorship, review and content handlers remain.

**Cross-cutting.** `unsupportedUploadMessage` was a `const` with Arabic text
used by six handlers across both surfaces. It became `unsupportedUploadMsg(lang
string) string`, a function that calls `i18n.T(lang, "common.unsupported_upload")`.

**go vet printf checker.** `i18n.T(lang, key, args...)` triggers `go vet`'s
printf analyzer because the key string has no `%` directives — the format
directives live in the catalog text, not in the key. Calls with format
arguments use `fmt.Sprintf(i18n.T(lang, key), args...)` instead, which `go vet`
does not flag because the format string is not a literal.

**What was deliberately not touched:** `i18n.Text{"ar": "...", "en": "..."}`
literals are already bilingual and correct — `Get(lang)` returns the right
language. These were left as-is. Sample product names in Excel/CSV templates
("بانادول اكسترا 500 مجم أقراص") are real Arabic pharmaceutical names and
were left as data, not UI strings. The `visitor.go` country-name-with-flag-emoji
trap and the `Icon string` struct fields remain as documented in pass 2.

## Pagination — three handlers converted

The three page-driven 500-row fetches identified in the handoff now use real
pagination:

- `customer_saving_handlers.go` — `ListSavingProductsEnriched(…, h.pageLimit(r),
  (page-1)*limit)` with `components.B2BPagination` rendered in the template.
- `vendor_saving_handlers.go` — same pattern, vendor base URL.
- `admin_catalog_handlers.go` — `ListAllSavingProductsAdmin(…, limit, offset)`
  with `components.B2BPagination` rendered in the admin template.

Each handler reads `page` and `limit` query parameters (the same parameters
`B2BPagination` generates), converts to offset, and passes
`components.PaginationProps{CurrentPage, PageSize, TotalCount, BaseURL,
QueryValues}` to the page data. The `TotalCount` comes from
`SavingProductStats.CountAll` (customer/vendor) or
`SavingProductAdminStats.TotalProducts` (admin).

Three `.templ` files were edited and `templ generate` was run from the
repository root with no `-path` flag, per the working agreement.
