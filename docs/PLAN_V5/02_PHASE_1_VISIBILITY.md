# PHASE 1 — Institutional Works & the Product Read Model

**Depends on:** Phase 0 complete (especially T9 — the coverage chain test).
**Blocks:** Phases 2, 3, 5, 6, 7 — every product/offer listing built later
depends on the filter and the read model defined here.
**Tasks:** 3.

## Why this phase exists

Two structural gaps, both of which will be baked into every screen you build
later if they are not fixed first:

1. **Institutional-work filtering is implemented nowhere.** Go has all three
   tables and an admin CRUD screen, and applies the filter to **zero** product
   or offer queries. Every customer currently sees every product regardless of
   institutional group. This is a data-visibility regression against Laravel.
2. **Go's `catalog.product_infos` is not Laravel's `product_infos`.** Same name,
   completely different thing. Laravel's is the denormalized read model that
   drives search, the dashboard, and the priority engine. Go's is a key/value
   attribute bag. Building Phase 3 without resolving this will produce a broken
   priority engine.

### 1.1.2 The rule, restated (from `Laravel/docs/institutional_work_filter.md`)

**Data:**
- A user has N institutional works, via `employee_institutional_works(user_id, institutional_work_id)`.
- A product carries `institutional_work_ids` as a **comma-separated string** e.g. `"5,7,9"`.
- `institutional_work_connections(from_institutional_work_id, to_institutional_work_id)` maps
  "a user in group *from* may see products of group *to*".

**Mode Simple** — used on the customer dashboard:
```
visible(product) := product.institutional_work_ids ∩ user.works ≠ ∅
                 OR product.institutional_work_ids IS NULL/empty     ← unrestricted products are visible
```

**Mode WithConnections** — used on purchase-request pages:
```
allowed := { to | (from, to) ∈ connections, from ∈ user.works, deleted_at IS NULL }
visible(product) := product.institutional_work_ids ∩ allowed ≠ ∅
                    ← NO fallback: unrestricted products are NOT visible
```

The asymmetry is deliberate (the Laravel doc states it explicitly). **Port both
modes and the asymmetry.** Do not "fix" the missing fallback.

### 1.1.4 Domain + service

`internal/modules/org/institutional.go` already exists — extend it, do not
create a parallel file. Add:

```go
// InstitutionalFilterMode selects Laravel's two documented filter semantics.
type InstitutionalFilterMode int
const (
    // FilterSimple: intersect the user's works directly with the product's,
    // and additionally allow products with no institutional restriction.
    // Laravel: applyInstitutionalWorksFilter_Simple — customer dashboard.
    FilterSimple InstitutionalFilterMode = iota
    // FilterWithConnections: resolve connections first, then intersect.
    // Products with no restriction are NOT visible. Laravel:
    // applyInstitutionalWorksFilter_WithConnections — purchase-request pages.
    FilterWithConnections
)

// AllowedWorkIDs returns the institutional work ids a user may see products for.
func (s *Service) AllowedWorkIDs(ctx context.Context, userID int64, mode InstitutionalFilterMode) ([]int64, error)
```

`AllowedWorkIDs` is the **only** place the connection resolution lives.

### 1.1.5 Cross-module problem — solve it correctly

`catalog` and `promo` need this filter, but rule R5 forbids
`modules/catalog` importing `modules/org`.

**Do not** copy the query into `catalog`. Instead:

Define the dependency as an interface **in the consumer**:

```go
// internal/modules/catalog/domain.go
// InstitutionalGate resolves which institutional work ids a user may see
// products for. Implemented by the org module and injected at composition
// time in cmd/server/routes.go — modules must not import each other (ADR 0002).
type InstitutionalGate interface {
    AllowedWorkIDs(ctx context.Context, userID int64, mode int) ([]int64, error)
}
```

Then in `cmd/server/routes.go`, alongside the existing `docsGate`:

```go
instGate := catalog.InstitutionalGateFunc(func(ctx context.Context, userID int64, mode int) ([]int64, error) {
    return orgSvc.AllowedWorkIDs(ctx, userID, org.InstitutionalFilterMode(mode))
})
catSvc.SetInstitutionalGate(instGate)
promoSvc.SetInstitutionalGate(instGate)
```

This mirrors exactly how `docsGate` is already composed (`cmd/server/routes.go:96`).
Follow that pattern; do not invent a new one.

### 1.2.3 Keeping it fresh

Laravel's refresh mechanism (found in §1.2.1) must be reproduced. In Go this is
a **worker job**, not a request-time write:

- `internal/modules/catalog/jobs/reindex.go` — a River worker
- Triggered on: product create/update/delete, variant change, stock movement,
  price change, organization rename, branch city change
- Plus a full-rebuild command for backfill: extend `cmd/cli` (or add a
  `-reindex` flag to an existing entrypoint — check what `cmd/cli` already does)
- The job must be **idempotent** and safe to run concurrently
  (`INSERT … ON CONFLICT (unique_row_id) DO UPDATE`)

**Deterministic fallback (rule R3 spirit):** if the index is stale or empty, the
search path must fall back to querying `catalog.products` directly rather than
returning nothing. Write a test with an empty index proving search still works.
